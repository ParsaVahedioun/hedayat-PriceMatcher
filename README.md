# Price Matcher

قیمت هر کالای انبار را از روی لیست قیمت PDF پیدا می‌کند و کنار همان کد کالا می‌گذارد.
کاملاً آفلاین، بدون نیاز به اینترنت.

---

## جهت کار برنامه

خروجی را **فایل Excel انبار** تعیین می‌کند، نه PDF:

```
هر ردیف Excel  ->  یک ردیف خروجی
ردیفی که فقط در PDF هست و در Excel نیست  ->  اصلاً نمایش داده نمی‌شود
ردیفی که در Excel هست ولی در PDF پیدا نشد  ->  می‌ماند، اما ستون قیمتش خالی است
```

اگر درصد تطبیق زیر `review_threshold` (پیش‌فرض ۷۰) باشد هیچ قیمتی نوشته نمی‌شود؛
حدس زدن قیمت بدتر از خالی گذاشتن آن است.

خروجی Excel دقیقاً همان سه ستون فایل انبار (کد کالا / نام کالا / موجودي) با
همان فونت، رنگ سربرگ و عرض ستون‌هاست؛ فقط یک ستون «قیمت» به آن اضافه می‌شود.
این خروجی همیشه **کل انبار** را در بر می‌گیرد - چه ردیف‌هایی که قیمت پیدا
کرده‌اند و چه ردیف‌هایی که قیمتشان خالی مانده - دقیقاً مثل خود فایل انبار.
(چک‌باکس «فقط ردیف‌های قیمت‌دار» فقط روی خروجی PDF اثر دارد.)
ستون‌های داخلیِ مربوط به کیفیت تطبیق (مدل در لیست قیمت، صفحه، درصد تطبیق،
نوع تطبیق، وضعیت، توضیح) نه در اپ نمایش داده می‌شوند و نه در خروجی
Excel/PDF نوشته می‌شوند.

## برند لیست قیمت

هر بار که یک PDF وارد می‌شود، وارد کردن **نام برند همان لیست قیمت** الزامی
است (مثلاً «شوان» یا «ویسنا» - همان کلمه‌ای که در انتهای نام کالاها در فایل
انبار می‌آید). تطبیق فقط روی ردیف‌هایی از انبار انجام می‌شود که همان کلمه‌ی
برند را در نامشان دارند؛ کالاهای برندهای دیگر همیشه بدون قیمت می‌مانند، حتی
اگر کد یا مشخصاتشان شبیه یک ردیف از لیست قیمت باشد. این یعنی هر بار فقط با
همان برندی که در PDF نوشته‌اید قیمت‌گذاری انجام می‌شود.

## چند PDF هم‌زمان

می‌توانید چند فایل PDF (چند برند مختلف) را با هم اضافه کنید؛ هرکدام با نام
برند خودش. هر فایل جدا خوانده و جدا تطبیق داده می‌شود (دقیقاً مثل حالت
تک‌فایل)، بعد نتیجه‌ها روی هم می‌نشینند:

```
اولین PDF در فهرست که برای یک ردیف قیمت پیدا کرد  ->  همان قیمت می‌ماند
PDFهای بعدی  ->  فقط ردیف‌هایی را پر می‌کنند که هنوز بی‌قیمت‌اند
```

یعنی ترتیب فهرست فایل‌ها = ترتیب اولویت. در جدول نتیجه یک ستون «منبع (PDF)»
نشان می‌دهد قیمت هر ردیف از کدام فایل آمده، و در صفحه‌ی نتیجه یک جدول کوچک
هم می‌گوید هر فایل چند ردیف خواند و چند ردیف را قیمت‌گذاری کرد - تا اگر یکی
از فایل‌ها اشتباه خوانده شود، زود معلوم شود کدام فایل بوده.

از خط فرمان هم قابل استفاده است:

```bash
python main.py --pdf price1.pdf:برندA --pdf price2.pdf:برندB --excel stock.xlsx --out ./result
```

## اجرا

```bash
pip install -r requirements.txt

python main.py                                             # پنجره دسکتاپ
python main.py --cli price.pdf stock.xlsx --brand شوان      # بدون پنجره، یک PDF
python main.py --cli price.pdf stock.xlsx --brand شوان --out ./result
python main.py --pdf price1.pdf:برندA --pdf price2.pdf:برندB --excel stock.xlsx --out ./result  # چند PDF
```

## خروجی Excel قابل فیلتر

فایل Excel خروجی، علاوه بر چهار ستون اصلی انبار (کد کالا/نام کالا/موجودي/قیمت)،
دو ستون دیگر هم دارد: **برند** (اینکه قیمت این ردیف از کدام PDF/برند آمده) و
**وضعیت** (دقیق/معتبر/نیاز به بررسی/بدون قیمت). ردیف سربرگ AutoFilter دارد و
سطر اول یخ‌زده (freeze) است، یعنی مستقیم در همان فایل می‌شود:

- فقط ردیف‌های **قیمت‌دار** را دید (فیلتر ستون قیمت روی «غیرخالی»)
- فقط **موجودی کم** را دید (فیلتر عددی ستون موجودي، مثلاً «کمتر از ۱۰»)
- فقط یک **برند** خاص را دید (فیلتر ستون برند)
- فقط ردیف‌های **نیاز به بررسی** را دید (فیلتر ستون وضعیت)

بدون نیاز به خروجی گرفتن جداگانه برای هر حالت.

## چرا خواندن این PDF سخت است

لیست قیمت‌های فارسی معمولاً جدول واقعی ندارند؛ `find_tables()` صفر جدول برمی‌گرداند
و متن خام به‌هم‌ریخته بیرون می‌آید. دو مشکل مشخص:

1. **فونت subset خراب** — چند حرف فارسی به کدپوینت لاتین تصادفی نگاشت شده‌اند:
   `مهتاƬی` به‌جای `مهتابی`، `آمƮر` به‌جای `آمپر`، `میǗیاتوری` به‌جای `مینیاتوری`.
   جدول ترمیم در `utils/text_utils.PDF_GLYPH_FIXES` است.
2. **شکستن کلمات** — کلمات فارسی در جای دلخواه بریده می‌شوند (`مد ل`، `تو ان`،
   `آ مپر`). یعنی مرز کلمه در متن PDF هیچ اطلاعاتی ندارد.
3. **بدون کد لاتین** — برخی لیست‌های قیمت (مثلاً کاتالوگ‌های شماره‌گذاری‌شده با
   «ردیف») هیچ کد مدل لاتینی ندارند؛ کالا فقط با شرح فارسی و شماره ردیف
   شناخته می‌شود. این ردیف‌ها به‌عنوان یک قلم «بی‌کد» نگه داشته می‌شوند و
   تطبیقشان کاملاً بر اساس مشخصات/متن انجام می‌شود (`Matcher.code_score`
   برای این‌ها امتیاز کد را کنار می‌گذارد، نه صفر می‌کند).
4. **ستون بدون واحد** — برخی لیست‌ها ستون «توان» را با شماره‌ی خام می‌نویسند
   (بدون کلمه‌ی «وات» کنارش)؛ واحد فقط یک‌بار در سربرگ ستون نوشته شده و در
   ردیف‌های داده تکرار نمی‌شود. `pdf_reader` موقعیت (x) همان سربرگ «توان»
   را به خاطر می‌سپارد و عدد هم‌ستون هر ردیف را به‌عنوان مقدار واقعی وات
   برمی‌دارد؛ اگر بیش از یک عدد در همان بازه‌ی ستون بود، به‌جای حدس زدن آن
   ردیف را بی‌واحد رها می‌کند.
5. **دو املای یک کلمه** — «باتری» و «باطری» (یا نام برند «امیدنور» /
   «امید نور» با یا بدون فاصله) دو نوشتار رایج یک کلمه‌اند؛
   `utils/text_utils` این‌ها را پیش از هر مقایسه یکی می‌کند، وگرنه چنین
   ردیفی فقط به‌خاطر املای متفاوت بی‌قیمت می‌ماند.
6. **جداکننده‌ی هزارگان عربی** — برخی ابزارها «۱،۶۹۹،۰۰۰» را با کاراکتر
   ویرگول عربی (`،` = U+060C) می‌نویسند، نه ویرگول معمولی و نه جداکننده‌ی
   هزارگان استاندارد عربی (`٬` = U+066C)؛ هر سه حالا به یک شکل شناخته
   می‌شوند.
7. **قیمت تکه‌تکه‌شده** — بعضی ابزارهای PDF یک عدد را به‌جای یک تکه، چند
   شیء متن جدا (هر گروه رقم و هر جداکننده، جدا) رسم می‌کنند؛ این تکه‌ها بر
   اساس نزدیکی‌شان روی صفحه دوباره به هم چسبانده می‌شوند، نه اینکه هرکدام
   تنها بررسی شود.
8. **ستون کد و ستون داده هم‌ردیف نیستند** — بعضی لیست‌ها ستون کدها را کاملاً
   مستقل از ستون شرح/قیمت می‌چینند؛ هر ستون ریتم عمودی خودش را دارد، پس یک
   کد می‌تواند ده‌ها واحد از سطر واقعی‌اش فاصله داشته باشد - خیلی بیشتر از
   حد معمول برای «کدی که یک خط بالاتر افتاده». وقتی صفحه‌ای دقیقاً به همان
   تعداد سطر «فقط-کد» و سطر «فقط-قیمت» دارد، این دو ستون بر اساس ترتیب
   بالا-به-پایین به هم وصل می‌شوند - نه بر اساس فاصله.

راه‌حل: متن PDF همیشه به شکل **بدون فاصله** (`dense()`) مقایسه می‌شود، و سطرها
از روی **مختصات** بازسازی می‌شوند نه از روی متن.

### بازسازی سطر (`core/pdf_reader.py`)

```
کلمات با bounding box  ->  گروه‌بندی بر اساس مرکز عمودی  ->  مرتب‌سازی راست‌به‌چپ
کد مدل  = راست‌ترین کلمه‌ای که شکل کد دارد
قیمت    = چپ‌ترین عددی که شبیه مبلغ است  (ستون قیمت همیشه بیرونی‌ترین ستون است)
عنوان بخش = نزدیک‌ترین تیتر بالای سطر
```

موارد خاصی که پوشش داده شده‌اند: کد دوخطی (`SCWLS-2835` + `120`)، قیمتی که یک خط
پایین‌تر چیده شده، یادداشت‌های تزیینی (`+IC Driver`، `Flicker Free`) که روی سطر
محصول چاپ شده‌اند، و ردیف‌های «بزودی» که قیمت ندارند.

## منطق تطبیق (`core/matcher.py`)

برای هر ردیف انبار سه سؤال مستقل پرسیده و وزن‌دار ترکیب می‌شود:

| بخش | وزن | چه چیزی را می‌سنجد |
|---|---|---|
| `code` | ۰٫۴۵ | کد مدل داخل نام کالا: `(SCAP)`، `(VS558)`، `(SCTRW/B)` |
| `spec` | ۰٫۲۵ | وات / آمپر / ولت / تراکم / ابعاد |
| `text` | ۰٫۳۰ | هم‌پوشانی واژگان با وزن IDF |

**چرا IDF و نه شباهت رشته‌ای ساده:** در یک لیست قیمت روشنایی، «پنل»، «وات» و
«مهتابی» تقریباً در هر سطر هستند و چیزی را مشخص نمی‌کنند. چیزی که محصول را
مشخص می‌کند یک کلمه نادر است — «اپلاست»، «اسلیم لاین»، «ترکیبی». شباهت فازی
معمولی به همه‌شان رأی یکسان می‌دهد و دقیقاً از همین‌جا تطبیق اشتباه درمی‌آید.

**مغایرت مشخصات وتو است، نه جریمه.** پنل ۹ وات و ۱۸ وات از یک خانواده، دو محصول
با دو قیمت متفاوت‌اند. اگر وات یا آمپر دو طرف نخواند، امتیاز در
`spec_conflict_factor` (۰٫۳۵) ضرب می‌شود و زیر همه آستانه‌ها می‌افتد.

**کلمات تمایزدهنده.** `سنسوردار`، `نسوز`، `ترکیبی`، `محافظ جان`، `مینیاتوری` و…
اگر فقط در یک طرف باشند جریمه می‌گیرند — همین است که نمی‌گذارد یک کلید مینیاتوری
با قیمت محافظ جان قیمت‌گذاری شود.

**فیلتر برند.** ردیف‌هایی که برندشان در لیست قیمت نیست (شوان، بروکس، …) اصلاً
تطبیق داده نمی‌شوند. با `restrict_to_price_list_brands` قابل خاموش کردن است.

### واژگان معادل

بین زبان انبار و زبان لیست قیمت پل زده می‌شود — این‌ها در
`core/attributes.py` هستند و از `config.json` قابل گسترش‌اند:

```
تک فاز        -> تک پل
سه فاز        -> سه پل
فنر متغییر    -> فنر متحرک
نقره ای پلاس  -> سیلور پلاس
چراغ خطی      -> براکت

محافظ جان + تک فاز  -> دو پل      (محافظ جان تک‌فاز فیزیکاً دوپل است)
محافظ جان + سه فاز  -> چهار پل
```

### وضعیت‌ها

| وضعیت | امتیاز | یعنی |
|---|---|---|
| `دقیق` | ۱۰۰ | کد مدل عیناً یکی است |
| `مطمئن` | ≥ ۸۵ | خانواده کد + مشخصات می‌خواند |
| `بررسی شود` | ≥ ۷۰ | قیمت نوشته می‌شود ولی یک نگاه لازم دارد |
| `یافت نشد` | < ۷۰ | ستون قیمت خالی می‌ماند |

اگر دو کاندید نزدیک هم باشند ولی **قیمتشان یکی** باشد، ابهام محسوب نمی‌شود:
هر کدام انتخاب شود، عددی که کاربر می‌بیند یکی است.


## تنظیم دقت

همه چیز در `config.json` است:

- `review_threshold` — زیر این عدد قیمتی نوشته نمی‌شود (پیش‌فرض ۷۰)
- `weights` — سهم code / spec / text
- `spec_conflict_factor` — شدت وتوی مغایرت عددی
- `discriminator_penalty` و `discriminative_terms` — کلمات تمایزدهنده
- `synonyms` و `context_rules` — واژگان معادل
- `text_coverage_exponent` — کالیبراسیون مقیاس امتیاز متنی
